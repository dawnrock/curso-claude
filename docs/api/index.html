Resttek API (1.0.0)

Download OpenAPI specification:

REST API of Resttek, a restaurant management platform.

Authentication

Most endpoints require a JWT obtained from POST /api/v1/auth/login (or POST /api/v1/auth/register for clients). Send it in the header Authorization: Bearer <token>. The token payload holds the user's id, role and restaurantId.

Roles

Role Used from Scope
admin web-admin Whole platform
manager web-admin, web-empleados Their restaurant
cocinero web-empleados Kitchen of their restaurant
camarero web-empleados Dining room of their restaurant
cliente web-clientes Their own orders

Each operation lists the roles allowed to call it. A valid token with a role that is not allowed gets 403.

Errors

Two error shapes coexist:

  • DomainError ({ error, message }): domain errors mapped by the global error handler. *NotFoundError → 404, InvalidCredentialsError → 401, any other domain error → 400, unexpected errors → 500.
  • SimpleError ({ error }): authentication/authorization middlewares and the orders endpoints.

Test credentials

After npm run seed, every seeded user's password is their own email (for example admin@resttek.com / admin@resttek.com).

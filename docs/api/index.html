Resttek API (1.0.0)

Download OpenAPI specification:

API REST de Resttek, plataforma de gestión de restaurantes.

Autenticación

La mayoría de endpoints requieren un JWT en la cabecera Authorization: Bearer <token>. El token se obtiene con POST /api/v1/auth/login o POST /api/v1/auth/register, caduca a las 8 horas y su payload contiene { id, role, restaurantId }.

Roles disponibles: admin, manager, camarero, cocinero, cliente. En cada operación se indica qué roles están autorizados; "cualquier usuario autenticado" significa que basta con un token válido.

Formato de errores

Según qué capa genere el error, el cuerpo tiene una de estas dos formas:

  • Errores de dominio (errorHandler): { "error": "<NombreDelError>", "message": "<descripción>" }. Los *NotFoundError se devuelven como 404, InvalidCredentialsError como 401 y el resto como 400. Los errores no controlados devuelven 500 con { "error": "InternalServerError", "message": "Something went wrong" }.
  • Middlewares de autenticación y endpoints de pedidos: { "error": "<descripción>" } (401 sin token o token inválido, 403 rol no autorizado).

Convenciones

  • Los identificadores son cadenas opacas: el servidor genera UUID v4, pero los datos del seed usan IDs legibles (p. ej. rest-1).
  • Las fechas se devuelven como cadenas ISO 8601.
  • Los PUT son reemplazos completos: los campos opcionales omitidos vuelven a su valor por defecto.
